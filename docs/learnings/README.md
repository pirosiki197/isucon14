## 今回の推移

初期実装から 8.1 倍。**1 手ごとにベンチを回して効果を確認した**のが重要で、
まとめて変更すると何が効いたか分からなくなる。

| # | 変更 | スコア | 備考 |
|---|---|---|---|
| 0 | 初期実装 | 1075 | |
| 1 | `ride_statuses(ride_id, created_at)` | 2168 | クエリ単価 21.8ms → 0.3ms |
| 2 | `chair_locations(chair_id, created_at)` | 2819 | |
| 3 | 窓関数サブクエリに絞り込みを押し込む | 4218 | SQL 1 行。1.75s → 63ms |
| 4 | ポーリング間隔 30ms → 100ms | 5761 | |
| 5 | 座標と累積距離を `chairs` に非正規化 | 6343 | |
| 6 | `chairs(access_token)` | 8203 | 認証が全リクエストに乗っていた |
| 7 | fsync 設定 (`flush_log_at_trx_commit` 等) | 8707 | fsync 3万回 → 939回 |

効果が大きかったのは **1・3・6・7**。いずれも「インデックスが無い」「設定がデフォルト」
という、**コードの出来とは無関係な部分**だった。凝った実装改善より先に、
まずこの層を潰す方が費用対効果が高い。

## 最初の 30 分でやること

1. `pt-query-digest` と `alp` を使えるようにする（ログ設定込みで 10 分）
2. 主キー以外のインデックスが無いテーブルを探す → `WHERE` 句と突き合わせて貼る
3. MySQL の fsync 設定を落とす
4. Go の `SetMaxIdleConns` を設定する

ここまでは**ほぼ何も考えずに効く**。考えるのはその後でいい。
